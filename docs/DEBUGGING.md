# Structured debugging — Breakout 10

`Verification FAIL → Failure Packet → Diagnosis → fresh correction Builder → frozen child Candidate → same protected verification`. Explicit Attempt Fix starts the loop. Only current, definitive required FAIL with no infrastructure uncertainty qualifies. A `candidate_defect` diagnosis may correct code; all other classifications stop for a human. Maximum two correction attempts; duplicate trees stop early as ineffective. New failures produce fresh packets/diagnoses with prior engineering artifacts.

Failure Packet v1 binds Candidate tree/diff/base, Run, accepted revisions, Recipe/evaluator/environment and protected evidence hashes. Canonical SHA-256 identifies its exact content. Limits: 64KiB packet,8 evidence excerpts≤4KiB each,6 relevant paths,source windows≤120 lines/8KiB,diff≤16KiB. Source comes from frozen BASE/Candidate objects, not a mutable checkout. Evidence is explicitly untrusted. Local Builder checks are non-authoritative. Relevant failed steps, accepted scope/non-goals and prior corrections are included; entire repositories and protocol/hidden reasoning transcripts are excluded.

`mission-debug-diagnosis-v1` yields concise observations,≤3 evidence-citing hypotheses,one selected ID,one bounded correction direction and classification. Evidence/path references must exist; accepted-artifact mutation, evaluator weakening and non-goal directions are rejected. Read-only/tool-disabled Codex uses the existing ChatGPT login, no API-key route. `mission-debug-correction-v1` supplies the validated packet/diagnosis and fixed accepted scope to the existing Builder.

Fresh correction workspaces use the exact parent frozen tree while retaining original accepted BASE for cumulative diffs. Existing generation fencing, permissions, composite Cancel and capture checks remain authoritative. Candidate B records parent A; C records B. All required claims re-run against the SAME Evaluation revision/hash, Recipe identity/hash and evaluator bundle. Only protected PASS can resolve a Session; model verdicts have no authority.

Migration11 is additive. Terminal history and packets cannot UPDATE/DELETE/REPLACE/upsert around native guards. Session/cycle reservation is shared with Builder/Verifier; no parallel runtime introduced. GET /api/missions/:id/debug; POST /api/missions/:id/debug-sessions with verificationRunId; POST /api/debug-sessions/:id/stop with empty body. No arbitrary commands or paths accepted.

Recovery discards partial diagnosis output, reconciles recorded owned processes and interrupts the loop. Unknown-launch/cleanup state remains durable and blocks all worker admission. A verifier crash during its launch gap requires reconciliation; it cannot become PASS. Resolved immutable history remains readable after restart. There is no automatic resume or permission replay.

Development fixtures cover real, two, exhaustion, ambiguity, permission, cancel, diagnosis-wait and verify-wait. Only `real` calls native Codex; others are explicit CLI-only deterministic lifecycle adapters, with actual protected verification. No production configuration selects adapters. Evidence and observational timings live under artifacts/breakout-10/. No receipt, reviewer or Mission finalization is implemented.
