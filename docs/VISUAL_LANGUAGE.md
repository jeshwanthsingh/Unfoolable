# Visual language

## Product feeling
Engineering mission control: personal, calm, tactile. A compact control rail surrounds a working bench, not a wall of interchangeable dashboard cards. Workspace labels, engraved rules and connected station shapes provide a sense of place. System fonts only.

## Core metaphor
Work moves through engineering stations. Intake records intent; Understand currently records repository context only. Clarify now uses actual bounded analysis and persisted required decisions. Define now records bounded contract drafting, explicit review and accepted revisions. Build now shows preparation only: real plan drafting, review and agreed instructions. A real owned Builder may now activate Workbench after explicit Start. Verify and Proof execution remain unavailable; the Verification Blueprint is a definition, not observed evidence. An original geometric Codex marker appears only while an owned runtime process is present; it disappears before Candidate arrival. Verify stays Awaiting, never successful.

## Truth rule
Every active state comes from persisted Mission/context data or a real pending HTTP request. Loading and failures remain distinct from missing context. Mission phase derives from persisted current analysis and answers: DRAFT, NEEDS_CLARIFICATION, CLARIFIED, CONTRACT_REVIEW, CONTRACT_READY, PLAN_REVIEW PLAN_READY, BUILDING or CANDIDATE_READY. The current Mission is the last viewed record, not an executing task; its ID is a local browser preference checked against actual records. Counts come from existing APIs. Needs You contains unresolved required questions from the current successful analysis and current contract and Plan/Evaluation candidates awaiting explicit review. Failed reads stay unavailable; they do not become an empty queue.

## Color semantics
Ink/slate surfaces and light neutral text form the base. Blue means selected/current. Amber identifies the attention location; it does not invent an attention item. Red identifies actual errors. Green means observed coordinator/database readiness or successfully persisted context, never overall Mission completion. Clarified marks decisions resolved only. Contract Ready marks agreed scope only; Plan Ready marks agreed preparation only. Planning coverage and DEFINED claims use accent/neutral color, never runtime-success green. Tokens live in theme.css.

## Motion semantics
Short view transitions and subtle persisted-record arrival only. Pending operations use text and aria-busy, not fake progress stages. No idle pulsing, typing, walking or bouncing. Reduced-motion disables animation, transitions and smooth scrolling.

## Detail hierarchy
Simple outside, rigorous inside. Context totals and revision are primary; changes, inventory, complete hashes, IDs, limits and fingerprints are native keyboard-accessible disclosures. Original user intent stays exact in the detail view; previews are display-only. Slice outcomes and flows remain primary; exact required evidence, source provenance, preconditions, notes and immutable pair identities are one disclosure deeper.

## Munder boundary
The local research inspiration matrix favors visible genuine work and original state-derived stations. We take sense of place, spatially legible progression and the prospect of grounded activity/presence later. We reject its office metaphor, layout, branding, characters, LimeZu assets, sprites, game mechanics, fake movement and orchestration. All shapes are original CSS/SVG; no source or art is copied.
